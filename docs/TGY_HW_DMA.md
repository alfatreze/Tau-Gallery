# TGY decoder: SDRAM DMA and register block (simulation only)

Status: bit-exact in simulation against the scheduler port model; wired into the core behind `TAU_TGY` (see Integration) and exercised by the real CPU in simulation; not synthesised, not fitted, nothing on a Pocket.

## What the DMA does
- **Tables:** `cmd_tables` reads the two quantisation tables (64 u16 each, zigzag, even byte address, the container's tables section) from SDRAM into the decoder.
- **Stream:** the tile stream is read from ANY byte address (halfword reads of up to 32 into a 128-halfword FIFO, an odd start byte is dropped) and handed to the entropy decoder as 32-bit words; the decoder zero-fills past the length.
- **Pixels:** the decoded RGB888 rows are collected into an 8-row ring (four byte-wide RAMs of 1,024 entries; a pixel's three bytes always land in three different arrays) and written one request per row at `dst + y * pitch`, any byte address and any pitch (odd pitches included): when a row starts or ends on an odd byte the first or last halfword is written with ONE byte enable, so the neighbouring bytes stay untouched. The viewer plane is `0x200000` halfwords, pitch 2,400 bytes (800 x RGB888); a tile at an odd canvas column works.
- `hold` pauses the decoder's row starts while 4 or more rows wait to be written (the pixel pipeline is 3 clocks deep and rows can be one pixel wide: 4 waiting + up to 3 in flight < 8 slots). One request is in flight at a time; writes go first, then stream reads (the FIFO holds about 7,000 decode clocks of stream, a row write takes about 200).
- **Errors:** a decoder error or its watchdog gives `ev_err` code 1, a tile that does not finish in 2^24 SDRAM clocks (about 170 ms at 100 MHz; the biggest dense tile takes about 4 ms) code 2, an `ABORT` code 15; the decoder is reset, the in-flight request completes (an unaccepted one is withdrawn), the FIFOs are flushed, the unit is idle and the next tile decodes correctly (tested).

## Registers (MMIO 0x220 .. 0x24C, word access, `tau_tgy_regs.sv`)
`0x220 CTRL` (write: bit 0 START_TILE, 1 LOAD_TABLES, 2 ABORT, 3 CLEAR) | `0x224 STATUS` (busy, done, err, tables loaded, start rejected, error code [11:8], present [31]) | `0x228 SRC` stream byte address | `0x22C LEN` | `0x230 DST` first pixel byte address | `0x234 PITCH` | `0x238 GEOM` {format, width, height} | `0x23C QY` | `0x240 QC` | `0x244 CYCLES`. `irq` = done | err. Write the configuration first, START in a separate store. A start while busy is ignored and sets `rejected`; a STATUS read right after a START already says busy (the flags are event driven through toggle synchronisers).

## Results (simulation)
- `test-rtl-dmux`: random CPU (32-bit, byte enables) and a random read/write client D share the port model; every read beat, every write byte and every `done` checked, the whole memory compared; 10 of 10 mutants killed (one, C accepted while D is in flight, needed an explicit check of the contract).
- `test-rtl-tgy-dma`: 11 tile streams (two real photo tiles included) with odd and even stream start, odd and even destination, pitches 400, 397 and 512; after each tile EVERY byte of the 512 KB model memory is compared (the tile's RGB bytes exact, everything else untouched). Abort, a corrupt stream, a starved port (timeout), each followed by a good tile. Dense real tile: 402,069 SDRAM clocks from start to the last row in memory (about 4.0 ms at 100 MHz). Both `C444` configurations. 10 of 10 mutants killed (hold off, green and blue swapped, third byte lost, last and first byte enable, enables forced, no FIFO space check, no odd-start skip, no timeout, first-row detection).
- `test-rtl-tgy-unit`: the CPU view with two unrelated clocks (66.7 and 100 MHz): registers read back, LOAD_TABLES, START with the immediate busy/not-done check, a start while busy rejected, done, irq, CYCLES, CLEAR, ABORT then a good tile; 6 of 6 register mutants killed (three took a sharper check: a start must clear a stale done flag, irq must rise on err, the done flag must survive until the next start).
- Caught on the way: the first-row test used the 5-bit row counter, which wraps at 32 rows (a 64-row tile overwrote its first row); a withdrawn-request deadlock when the port stays busy during an error.

## Integration (done 2026-11-11, simulation only; B-1057)
Behind the macro `TAU_TGY` (needs `TAU_LAND`; off in every existing bundle, and the default SoC is unchanged: the Halcyon SoC test passes with the new ports unconnected):
1. `tau_soc.v`: parameter `TGY_ENABLE`; ports `fb_tgy_addr / we / wdata` out, `fb_tgy_hit / rdata / irq` in; MMIO 0x220-0x24C forwarded (read data merged into the read mux, reads 0 when off); interrupt source 4 (rising edge of the unit's level) in `IRQ_PEND` 0x214; CORE_VERSION **rev 29 = 0x4D50331D** whenever `TAU_TGY` is defined (checked first in the version chain).
2. `core_game.vh`: `TAU_TGY_EN`, the three-client chain on the scheduler's CPU port (CPU and landing path through `tau_sdram_p2mux`, then `tau_sdram_dmux` for the decoder), `tau_tgy_unit` with `C444 = 0` (grey and 4:2:0 tiles; 4:4:4 pictures are transcoded by the converter), clocks `clk_sys` and `clk_sdram`; `TAU_TGY` without `TAU_LAND` stops the build (undefined macro on purpose).
3. `tools/gallery_m1c_qsf_append.txt`: the m1b bundle (128 KB RAM) plus `TAU_TGY=1` (the sources are found through `SEARCH_PATH core`); `tau_compat` resolves it to 0x4D50331D. Firmware: `fw2/build_gallery.sh TGY=1` links the gallery into 128 KB for rev 29 (`P2_TGY`); the default and `RAM128=1` builds are unchanged. `docs/MMIO_ALLOCATION.md` lists the registers.
4. Test: `make test-rtl-tgy-soc`: tau_soc with the real VexRiscv running `sim/fw_tgy/main.c` programs the decoder (tables, tile, status polls, CYCLES, interrupt bit 4, CLEAR) and the picture memory is compared byte for byte; the firmware's 12 console lines (version, status values, busy right after a store, tile done, interrupt) are checked. Not run: the whole core (`core_top`) was not elaborated (the Altera IP models are missing here; a Verilator pass over it shows only missing-IP errors, none from the new code); the first full elaboration is the Quartus synthesis.
Still to do: the firmware driver (`tgy_hw.c`: container tile index to registers), the Quartus synthesis and two-seed fit (needs the owner's yes and a stated finish time), the Pocket run. Clock domain: the first fit showed the decoder does not close at the SDRAM clock; it now runs on its own 50 MHz clock with FIFO and dual clock RAM crossings: see `docs/TGY_HW_CLOCK.md` (B-1061).

## Firmware driver (`fw2/gallery/tgy_hw.c`, `tgy_hw.h`; B-1059)
A container v1 reader and the register driver, 3.1 KB of rv32im code, pure C on `REG_RD` / `REG_WR` (so the host test supplies a model of the hardware). The compressed file is resident in SDRAM (landed at an even byte address `base`, seen by the CPU through the uncached SDRAM window as `img`); the driver reads the header, level table, tile index and table directory through `img` and never touches the tile streams, which the decoder's DMA fetches itself.
- `tgy_open(img, n, base)` (img = a RAM copy of the first 4 KB; the CPU never reads SDRAM, the tile index of the level in use is read from the card through `tgy_load_index` into a RAM buffer and its checksum checked): `n` bytes of the file are resident (the whole file or a prefix: the fit level comes first, so landing the first part is enough to show the picture); checks magic, version 1, header size, header checksum, `n <= file size`, level table and table section. `tgy_level` / `tgy_find_level(kind)`: a tile level the core can run (grey or 4:2:0; 4:4:4 needs the larger chroma memory and is not offered), geometry and ranges checked, a level not entirely inside the resident bytes is not offered. `tgy_check_index`: the tile index checksum (12 bytes per tile read through `img`; the tile CHECKSUMS are not checked on this path, the CPU would have to read every stream).
- `tgy_hw_tables`: LOAD_TABLES for the level's tables (dropped from a cache keyed by the table addresses; `tgy_open` forgets it, because the landing window is reused for every picture and the same addresses would hold other tables). `tgy_hw_tile(tx, ty, dst, pitch)`: tile geometry (partial edge tiles), stream address and length from the index entry, all registers, CLEAR then START in separate stores, poll STATUS (0.5 s limit, ABORT on timeout), drops the done interrupt bit. `tgy_hw_level` (every tile, a tick callback) and `tgy_hw_show` (the level at its own rectangle of the 800 x 720 canvas, stride 2,400; refuses a level that would leave the canvas: the decoder writes whole tiles, a clipped write for zoom windows needs crop registers, not built).
- Errors: `TH_ABSENT` (no decoder on this core), `TH_BUSY` (busy or the start was rejected), `TH_HWERR` (decoder error; `tgy_hw_status()` has the code), `TH_TIMEOUT`, `TH_ODD` (odd base or odd table address), `TH_CRC`, `TH_RANGE`, ...
- `make test-tgy-hw` (`sim/test_tgy_hw.py`, `sim/tgy_hw_harness.c`): the driver against a register-level model of the decoder (decodes with the C reference pipeline; reads tables and stream at the programmed byte addresses; writes rows byte for byte; keeps busy for a few polls; sets done/err/rejected like the RTL) over a byte-addressed memory, files written by `tgy_make.py`. The picture the driver produces equals `Container.pixels` (TGY profile) byte for byte: the fit level at its rectangle of the canvas (everything outside untouched), the full level of a 1000 x 900 picture (64 tiles, partial edges) at an odd start address with an odd pitch, a small and a grey picture, both levels of one file (different tables: reloaded), a second picture at the same base (tables dropped), a prefix of the file. Refusals: header and index checksums, odd base, no decoder, busy, rejected start then a retry (CLEAR), decoder error, 4:4:4, a level wider than the canvas, n larger than the file. 20 of 20 mutants of the driver killed. Under AddressSanitizer / UBSan.


## The gallery application (B-1060)
`gallery_app.c` opens a picture whose header says container version 1 through `open_v1` (a version 0 picture takes the old path unchanged; a library may mix both): a core without the decoder says `NEEDS THE HW DECODER`; the card read lands only the first part of the file (header, thumbnail, fit level: everything up to the end of the fit level's tile data, rounded to 4 KB; about 100 to 300 KB) in the landing window (`GAL_LAND_BASE`, SDRAM byte 0x800000) at 1.5 MB/s with the loader bar; the tile index (at most 2 KB, the fit level's) is read from the card; the decoder fetches stream and tables from the landing window and writes the 42 tiles of the 800 x 720 canvas into the viewer plane (`DECODING n%`). Status lines: `NOT A TGY PICTURE` (header), `PICTURE DAMAGED` (index checksum, ranges), `DECODER ERROR`, `DECODER TIMEOUT`, `PICTURE READ FAILED`, `PICTURE DAMAGED IN TRANSFER`. Zoom is not offered for version 1 pictures yet (the zoom levels of the app are version 0 raw levels; a decoder zoom needs clipped tile writes).
The converter writes such files with `python3 tools/gallery/tgy_convert.py SRC OUT --format v1` (`tgy_make.canvas_container`): the fit level is the WHOLE canvas (the picture fitted and centred on black, the bars are part of the encoded picture, so every byte of the plane is written and the firmware never clears it); a picture larger than the canvas also gets its full-resolution level (a JPEG losslessly) for the later zoom, a smaller one only the canvas. `--format v0` (the default) is unchanged.
Tests: `python3 sim/test_gallery_app.py` (the whole existing suite, which still passes, plus the scenarios `v1` and `v1nohw`): the app's model of the hardware gained the decoder (registers 0x220-0x244, decoding with the C reference pipeline over the SDRAM model, byte-exact writes). A mixed library (v1 1000 x 900 JPEG, v1 500 x 300, a v0 picture, a v1 picture with a damaged stream, tile index and header) is opened from the grid and by Right in the viewer: the plane equals the reference decode of the file (800 x 720 x 3 bytes), 42 tiles and one table load per picture, a v0 picture after a v1 one lands as before, each damage gives its status line, a core without the decoder gives its message. `--v1-mutants`: 7 of 7 mutants of the v1 path killed (two further edits are equivalent: the app's index-load error and its second `tgy_open` are covered by the driver's own checks, so removing them changes nothing observable). Firmware: `fw2/build_gallery.sh APP=gallery TGY=1` builds (40 KB image, 56 KB with data, the 128 KB link); the default build also contains the v1 path and says `NEEDS THE HW DECODER` for a version 1 picture on an older core.
Not run on a Pocket; needs the core of the `gallery-m1c` fit.
