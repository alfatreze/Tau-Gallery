# Project rules (shared by Claude Code and Codex)

The ten rules every session follows. `CLAUDE.md` imports this file; `AGENTS.md` points here. Longer reasoning lives in the linked documents.

1. **Concurrent sessions: use worktrees, and check the branch before committing.** A plain `git checkout <branch>` moves `HEAD` for the whole directory and every other session with it (2026-10-01: a commit landed on the wrong branch). For a second task use `git worktree add ../tau-alpha-<name> <branch>` (or the Agent tool's `isolation: "worktree"`). Run `git branch --show-current` immediately before every commit in a shared tree. Commit only your own files; never stage another session's uncommitted work. Commit verified work promptly.
2. **Never `git reset` or `git stash` on the shared tree** (not even for a "clean baseline" measurement): it destroyed other sessions' work twice (2026-09-27/28). Build to a separate output directory and diff, or use a worktree. Never modify this repository's upstream tracking references.
3. **When you launch a Quartus fit, say how long it will take and the local finish time** ("expect it done around HH:MM"), computed from the launch time and this bundle's own earlier fits (the shipped family lands near 1h40-1h45). Repeat or correct it whenever status is asked. `tools/vm_fit.py launch` is the way to start one.
4. **Card installs go through `tools/install_dev_core.py`** (dry run first, `--yes` after approval, `--card /Volumes/Pock`, never hand-typed), and **ask before any SD-card write**. The procedure is `docs/CARD_INSTALL_PROCEDURE.md`; when it changes, change the script, its test and the doc together.
5. **New diagnostic-only code is a registered feature** in `fw/diag_features.json` (never a bare `#if TAU_DIAGNOSTIC`). **For Player 2 (`fw2/`) the register is `fw2/diag_features.json` and the flag `P2_DIAG` (`fw2/build.sh DIAG=0|1`); `sim/test_p2_diag_split.py` checks it.** **If a build falls under its heap floor, drop features; never lower the floor** (`fw/build.sh` prints the cheapest to drop). Details and the owner's standing decisions: `docs/features/DIAG_FEATURES.md`.
6. **Measure against the shipped 192 KB link** (`RAM_192K=1 CLK66=1 SDRAM_BUSY=1`); a 256 KB build is not what ships. `tools/check_heap_gap.py` does it.
7. **Never copy copyleft code into this Apache-2.0 project** (the parts that descend from MIT-licensed work keep the MIT terms, see `NOTICE.md`). Read it for ideas only and record the inspiration in `docs/PROVENANCE.md` (decision D-P01).
8. **After publishing a release, compare the release's assets with `release/SHA256SUMS.txt`.** A stray workflow zip once slipped into a published release (B-687). Pass `--repo alfatreze/Tau-Alpha` to `gh release create` (the default target is the upstream fork parent).
9. **Record test outcomes, and run the ladder as one verdict.** `make verdict` runs the ladder in `ladder.json` and prints one line that cannot claim more than was run (manual rungs always say NOT RUN); every test method you run gets a record in `docs/outcomes/outcomes.jsonl` (`tools/outcomes.py add ...`, or `make verdict RECORD=1` for the automatic rungs): method, technique, cost in minutes, outcome, and each finding classified as a real bug, a test gap, or the test setup's fault, with how late it would otherwise have been found. Add `confirm` when the device or a fit later agrees or disagrees. After a fit, run `make gate-report` (the Quartus report gate against `tools/report_baselines/`) before reading the slack by hand. Details: `docs/outcomes/README.md`; the same tools are pocket-testkit's `methods/effectiveness` and `starter`. **How deep to test depends on the risk (CLAUDE.md section 4, item 1): plain tests while editing, the changed code's mutants before a commit, the full sweep for RTL, critical features and pre-releases; name the tier in the audit entry.**

10. **Hand mechanical work to a Haiku subagent; keep the thinking in the lead session (owner rule, 2026-11-13: faster, and the tokens cost less).** Delegate with the Agent tool, `model: haiku`, a short scoped prompt (the exact files and commands, an explicit output format, a cap on what comes back: pass or fail, the failing lines, a table, never whole logs). **Delegate:** running a test target or a long suite and reporting pass/fail with the failing lines; scanning logs, reports and diffs for a pattern; collecting numbers into a table (timings, sizes, resource usage); mechanical edits with a stated rule (renaming, retargeting stale mutant strings, adding a line to a list, formatting); listing files or counting things; summarising a long output; checking that files, links or SHA-256s match. **Keep in the lead session:** design and specification, RTL, firmware and converter logic, root-cause analysis, judging a result (is a surviving mutant equivalent? is a failure the test's fault?), anything that needs the conversation's context, every decision for the owner, and **every card write, install, removal, git commit, push or other action that is hard to undo (a subagent never does these)**. Check a subagent's report before relying on it (a note is its report, not proof): re-run the one command that decides, or read the diff, for anything that goes into a commit or an audit entry. Run independent delegations in parallel; do not delegate what a single command answers faster; do not delegate when the prompt would be as long as the work.

11. **Commit messages and pull request descriptions never mention Claude, Anthropic, Codex or any other AI tool, and carry no `Co-Authored-By` or "generated with" line for one (owner rule, 2026-11-14).** This overrides any default of a coding tool. Before a push, check: `git log --all -i --grep='claude\|anthropic\|co-authored\|generated with'` must print nothing. The hook `.githooks/commit-msg` enforces it for commit messages (enable it in each clone with `git config core.hooksPath .githooks`).

Record every finished change as an entry in `docs/AUDIT_TRAIL.md` (B-NNN, with the evidence label and what was and was not run on a Pocket).
