## Design decided for the app (not yet written)
- **Grid table** (one row per size; the plan's 6 x 5 does not fit the 312 px grid area, so 64 px is 6 x 4): 4 x 3 at 96 px (1:1, 12 a page), 5 x 4 at 72 (ratio 3:4, 20), 6 x 4 at 64 (2:3, 24), 8 x 6 at 48 (1:2, 48). Positions: x = x0 + col * dx, y = 22 + y0 + row * dy with x0/dx/y0/dy per size (96: 3/99/6/102; 72: 6/78/4/76; 64: 2/66/10/74; 48: 1/49/3/51), ring 2 px (1 px at 48), corner radius 8 / 8 / 6 / 4. A version 0 index keeps the old 4 x 4 layout of 96 x 72 thumbnails with square corners (so every existing app test stays valid).
- **Thumbnails:** a 96 x 96 thumbnail is written by the CPU straight to the cell; smaller sizes are written to the stash (columns 400.., rows 384..) and scaled with `gfx_dsblit`, with `gfx_fence()` before the next thumbnail overwrites the stash. Then `gfx_corners(cell, radius, BG)`. Measured cost to be seen on the Pocket (the CPU alternative may be faster; the card read of 18 KB a thumbnail dominates for the small grids).
- **Selection ring without redrawing the thumbnail:** four 2 px rects outside the cell, `gfx_corners(cell, r, ACC)` fills the thumbnail's four corner notches with the ring colour, `gfx_corners(ring box, r + t, BG)` rounds the outside. Deselect: the same rects in BG and `gfx_corners(cell, r, BG)`.
- **State:** `cur_first`, `cur_count` (the open folder is the range [first, first + count) of entries; version 0 = the whole list), `sel` stays an absolute entry index, `page = (sel - cur_first) / per_page`. The entry page buffer (up to 48 x 176 B) is read into `v1z_idx` (32 KB, free until a zoom opens), like the boot head read. Viewer Left/Right wraps inside the folder.
- **Folder level** (only when `folder_count > 1`): the same grid machinery at 4 x 3 with `ent[]` filled from the folder records (name = folder name, thumb = cover, size = count); a darkened strip at the bottom of the tile carries the name and count. A opens a folder, B in a folder's grid goes back, B on the folder level leaves as today. Resume finds the folder of `last_idx` from the folder table read once at boot.
- **Details pages** (Select): INFO, SHOT (not offered when shutter / aperture / ISO / focal are all missing), HISTOGRAMS; Left/Right turn pages, B or Select closes; indicator top right `n/m` plus one dot per page; fields the picture lacks are not drawn. Details are read on demand (at most 255 bytes) with `gx_details_abs`.
- **Settings:** grid size (0..3), dither (off / ordered / ordered + temporal), colour preset (off, brightness, contrast, gamma, tints, invert via PIX_LUT) as new persisted words; registers PIX_CTRL 0x250, PIX_LUT 0x254 (see the RTL spec), checked against CORE_VERSION rev 30.
- **Converter:** `tgy_convert` and the converter app write TGIX v1 (walk one folder level, EXIF details, square thumbnails, sort mode, `--merge` upgrades a v0 index by padding its thumbnails); `merge_index.py` and `tau_compat` learn v1.

Design (firmware only, no new RTL): a key in the viewer (to be chosen: L1 is free in the fit view) cycles the masks off, 1:1, 4:5, 3:2, 16:9, 2.39:1 (CinemaScope), 65:24 (XPan, the 35 mm panoramic frame, about 2.71:1) and 3:1 (each in its portrait form too when the picture is portrait); the masked-out parts of the 800 x 720 fit plane are painted black with BLIT commands from a zeroed SDRAM source (`gfx_blit_raw`, 127 halfwords a command, a few hundred to a couple of thousand commands, tens of milliseconds), plus a thin accent line on the crop edge; leaving the mask re-runs the fit-level decode (about 0.3 s) to restore the pixels.
